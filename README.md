# Daily Planner

一个**本地优先（local-first）**的每日任务与学习计划工作台，提供「计划 → 学习单元 → 可执行子任务」三级组织、每日视图、进度汇总和任务记录。界面采用 Impeccable 的 **Operate** 设计准则进行精修。

> **重要：这是独立、可运行的重建版。** 现有 ChatGPT Site 的源工程无法从当前授权接口导出，所以这里没有把已发布网页误称为“原始源码”。仓库中的初始化数据是**匿名化的通用演示任务**，不包含真实学习进度、工作笔记或账户信息，与原 ChatGPT Site / 云端任务服务**没有实时同步关系**。初次使用会加载 11 天、88 项通用演示任务，后续由浏览器本地存储保存。

## 快速开始

要求 Node.js 18+，无 npm 第三方依赖。

```bash
npm run dev
# http://localhost:4173
```

也可以直接用 Python：

```bash
python3 -m http.server 4173
# http://localhost:4173
```

打开网页即可体验；不需要连接外部账号。**请不要直接用 `file://` 双击打开**，现代浏览器对 ES Modules 的本地路径有限制。

### Docker 部署

```bash
docker compose up -d --build
# http://localhost:8080
```

修改对外端口：

```bash
HOST_PORT=8888 docker compose up -d --build
```

可以在 1Panel 通过 Git 拉取仓库、创建 Compose 项目，再由 OpenResty 反向代理到宿主机端口。**当前是单机浏览器存储版本**；Docker 容器本身不会托管、备份或同步任何用户任务数据。

## 功能

- 今日工作台：今日任务、预计剩余工作时间、此前仍在进行中的任务、重点任务。
- 每日安排：七日日期带、按原理 / 源码仿真 / 工作问题 / 复盘分组、状态筛选。
- 学习计划：计划、学习单元、可执行任务，以及自动汇总的完成比例。
- 任务详情：较宽的右侧编辑面板，可编辑说明、完成标准、实际产出、日期、分钟、状态、归属单元和重点。
- 数据：浏览器 `localStorage` 自动保存；可导入、导出 JSON 进行迁移与备份。
- 基础无障碍：语义化表单、可见焦点、键盘快捷键、响应式与减少动态效果支持。

快捷键：`/` 聚焦搜索；`Esc` 关闭详情面板；`Ctrl/Cmd + Enter` 保存打开的编辑表单。

## 数据与安全

用户数据保存在**当前域名 + 当前浏览器**的 `localStorage` 中。更换浏览器、使用不同设备、切换域名或清除站点数据都不会自动迁移这些记录。建议每次重大编辑后通过侧边栏**导出数据备份**。

导入 JSON 时，将覆盖当前浏览器中的全部计划与任务，操作前页面会要求确认，建议先导出当前数据。

> `src/seed.js` 仅包含可公开的通用演示任务；个人数据请通过本地 JSON 导入，不要提交到仓库。不要提交访问令牌或真实云端 API 凭据。未来如启用云端存储，必须增加鉴权、持久化服务与服务器端数据隔离。

## 本地结构

```text
.
├── index.html               # SPA 入口
├── src/
│   ├── app.js               # 界面、交互、路由状态
│   ├── store.js             # 数据规则、进度计算、校验、持久化
│   ├── seed.js              # 初次进入时的示例任务数据
│   ├── icons.js             # 统一 SVG 图标
│   └── style.css            # 设计 token、桌面/移动响应式
├── tests/store.test.mjs     # 数据规则单元测试
├── dev-server.mjs           # 无依赖静态开发服务
├── Dockerfile
├── docker-compose.yml
└── nginx.conf
```

## 后续迁移原 Site 的步骤

1. 从现有 Site 编辑界面导出真实项目源码或提供其关联仓库。
2. 审查其 API URL、授权机制、数据类型和任务事件顺序，不要在浏览器中硬编码令牌。
3. 将源项目与当前重建版进行逐项 diff，把保留的业务行为与原有数据迁移流程合并。
4. 为现有云端服务开发明确的**服务端**数据适配器及登录/鉴权；完成前维持本地模式，避免出现虚假的“已同步”提示。
5. 增加端到端测试、数据库备份以及可靠的冲突处理，然后再开启多端同步。

## 设计来源

UI 审查与优化方向参考 [Impeccable](https://github.com/pbakaus/impeccable)（Paul Bakaus，Apache-2.0），侧重 Operate 模式的清晰信息层级、克制配色、任务状态反馈、响应式布局和无障碍。项目没有执行上游的本地 `npx impeccable` CLI / detector / browser hook，也不宣称通过其自动审计。
